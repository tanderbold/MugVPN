FAQ

Can I have more than one OpenVPN connection at the same time on a Mac?

Yes — that is what MugVPN is for. Every connection runs its own openvpn with its own utun interface, routes and DNS. Connect the office VPN, a client's VPN and your home lab together; each has its own submenu. If two connections want the same thing (both take all traffic, overlapping routes), MugVPN warns you.

How does split DNS work with several VPNs?

When a server names its domains (dns … resolve-domains, or with the per-connection switch also the old dhcp-option DOMAIN), only those names go to that VPN's DNS; everything else resolves as before. You can also set a connection's own DNS servers for domains you list. Several connections can each answer for their own domains; only one can take all names.

Does MugVPN have a kill switch? Does it stop DNS and IPv6 leaks?

Yes. Per connection, a kill switch blocks the Internet (with the macOS packet filter, PF) if a connection that carries all traffic drops unexpectedly, until you reconnect it or choose Unblock Internet in the menu. While such a connection is up, IPv6 and DNS outside the VPN are blocked. After connecting, and on every network change, a leak check warns if the default route, a public network or DNS goes around the tunnel — including routes a rogue DHCP server pushes (TunnelVision).

How does MugVPN compare to Tunnelblick, Viscosity and OpenVPN Connect?

OpenVPN Connect on macOS keeps one connection at a time. Tunnelblick and Viscosity can run several; MugVPN is built around it: per-connection split DNS, conflict and leak warnings, a kill switch that works with several tunnels, and a window to create and edit connections. It is free and open source (MIT), and it imports Tunnelblick configurations and standard .ovpn files.

Which profiles work?

Standard OpenVPN 2.x client profiles (.ovpn, .conf), with inline or separate certificates and keys, tls-auth, tls-crypt, tls-crypt-v2, PKCS#12, passwords, OTP, web sign-in and proxies. For safety, options that would run programs or load code (up/down scripts, plug-ins) are refused, with the line that caused it. Your own scripts beside the profile (<name>_up.sh …) run as you.

Is it safe to give a VPN app root? Does openvpn run as root?

Something has to be root to create tunnels, routes and DNS — but not openvpn itself. In MugVPN each tunnel's openvpn runs unprivileged, and a small helper does what needs root after checking each request. Profiles are checked before they run.

Why is there no download?

Because MugVPN installs a helper that runs as root, its builds should be signed with an Apple Developer ID and notarized. Until then, build it from source — a few minutes with the Xcode Command Line Tools (see the instructions).

Which macOS versions and Macs?

macOS 13 Ventura or later, on Apple silicon and Intel Macs. The interface is in 23 languages.
